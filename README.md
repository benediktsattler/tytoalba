# Tyto Alba — Clean theme for Adminer

![Tyto Alba theme for Adminer — Login with saved logins](https://raw.githubusercontent.com/benediktsattler/tytoalba/main/screenshots/login.png)

## Introduction

Tyto Alba is a quiet, warm-toned theme for [Adminer](https://www.adminer.org/), named after the barn owl. Built on the bones of Hassan Azzi's Simple Theme.

- warm off-white/grey palette with one accent color, adjustable via two variables
- clean layout with Lucide icons
- collapsible sidebar
- optional environment marker for production, staging and backup servers

### Installation

1. Get a copy of [Adminer](https://www.adminer.org/)
2. Download `adminer.css` from [here](https://raw.githubusercontent.com/benediktsattler/tytoalba/main/adminer.css).
3. Put the file `adminer.css` alongside `adminer.php`, or in the same directory that contains Adminer on your web server.

> **_NOTE:_** Adminer is better used for development environments, use with caution in prodcution

### Environment marker (optional plugin)

To tell production, staging and backup databases apart at a glance, the theme
marks the environment with a colored strip along the top of the screen, a
label hanging from it like a notch (always centered in view, even on wide
tables) and tinted breadcrumbs: prod red, staging violet, dev green, backup
blue.

Which connection is which is decided on the server by the small plugin
[`plugins/tytoalba-env.php`](plugins/tytoalba-env.php) (Adminer 5.3+), so no
host names end up in the CSS:

1. Copy `tytoalba-env.php` into a folder `adminer-plugins/` next to `adminer.php`.
2. Configure it in `adminer-plugins.php` (also next to `adminer.php`):

```php
<?php
return array(
    new AdminerTytoAlbaEnv(array(
        '*@db.example.com'  => 'prod',
        '*@localhost/dev_*' => 'dev',
        'backend@localhost' => array('backup', 'Backup · {db}'),
        '*@localhost'       => 'backup',
    )),
);
```

Rules are matched against `user@server/database` in order, the first match
wins; `*` and `?` are wildcards. A rule value is an environment name
(`prod`, `staging`, `dev`, `backup`) or `array(name, label, hue)` for a custom
label or an environment of your own, e.g. `array('qa', 'QA', 280)`. Labels may
contain `{db}`, `{user}` and `{server}`; without a selected database a
trailing separator is dropped (`Backup · {db}` → `Backup`).

### Development

`adminer.css` is a generated file, built from the sources in [`src/`](src/):

```
src/
  00-header.css        file header (version, credits, licenses) — @VERSION@
                        and @DATE@ are filled in by build.sh
  00-tokens.css        colors, spacing, font tokens (:root)
  05-icons.css         Lucide icons as --i-* mask tokens (GENERATED by
                        tools/gen-icons.py, don't edit by hand)
  10-fonts.css         Fira Mono (inlined as base64 by build.sh)
  20-reset.css         low-level resets
  30-elements.css      body, links, inputs, buttons, messages/errors
  40-page-layout.css   sidebar/content split, header, collapsible sidebar
  50-sidebar.css       nav, DB select, table list, sidebar icons
  60-forms.css         fieldsets, SQL editor, icon buttons, footer
  70-tables.css        table/thead/tbody, schema view, column sort
  80-environments.css  environment marker (body.env-* from the plugin)
```

Edit the files in `src/`, then run `./build.sh` to regenerate `adminer.css`.

The version lives in the `VERSION` file — bump it in the same commit as the
change. A pre-commit hook rebuilds `adminer.css` (with that version and the
commit date) and adds it to every commit automatically. Enable it once per
clone:

```
git config core.hooksPath .githooks
```

Icons are [Lucide](https://lucide.dev) SVGs used as CSS masks. To add or
swap one, edit the `ICONS` map in `tools/gen-icons.py`, then:

```
python3 tools/gen-icons.py <dir-with-lucide-svgs> src/05-icons.css
./build.sh
```

and use it as `--icon: var(--i-<name>)` on any of the pseudo-elements
listed in the "Icons (mask base)" section of `src/30-elements.css`.
